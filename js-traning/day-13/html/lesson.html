Day 13 — Execution Context & Hoisting

Lesson

All demos log to the console. Open DevTools (F12) or run node day-13/js/lesson.js. Source: ../js/lesson.js.

1 What is an execution context?

Global EC — created when the script loads; exactly one per program; holds top-level declarations and this at global scope. Function EC — created on each function call; holds locals, arguments, and that call’s this. Each EC has a variable environment, a link to the outer scope, and this.

const city = "Jaipur";
function greet(name) {
  const message = `Hi ${name} from ${city}`;
  return message;
}
greet("Priya"); // function EC #1, then torn down
greet("Aarav"); // function EC #2 — fresh

2 The two phases: creation & execution

Creation — engine scans declarations and allocates memory (no user code runs yet). Execution — lines run top-to-bottom. var starts as undefined; let/const exist but sit in the TDZ until their line runs.

console.log(lessonScore); // undefined (var hoisted)
var lessonScore = 90;
console.log(lessonScore); // 90

../js/lesson.js — Topic 2

3 The call stack (LIFO)

Script start → push global EC. Function call → push that function’s EC. Return → pop. Last in, first out. While innermost code runs, its frame is on top.

function multiply(a, b) { return a * b; }
function square(n) { return multiply(n, n); }
function printSquare(n) {
  console.log(square(n)); // 25
}
printSquare(5);
// multiply(5,5) on top → square(5) → printSquare(5) → global

../js/lesson.js — Topic 3

4 Hoisting — what it really is

Declarations are not “moved” in the source file; the engine records them in the creation phase so bindings exist before execution reaches their lines. var → undefined; let/const → TDZ until initialisation; function foo() {} → full function available.

console.log(varA); // undefined
var varA = 1;
console.log(letB); // ReferenceError (TDZ)
let letB = 2;
hi(); // OK — function declaration hoisted
function hi() { console.log("Hi"); }

../js/lesson.js wraps the let demo in try/catch so the script keeps running.

5 var vs let / const + TDZ

TDZ (temporal dead zone): from block entry until the let/const line runs, the binding exists but must not be read. var is function-scoped and can leak out of blocks; let/const are block-scoped.

{
  // console.log(mark); // ReferenceError
  let mark = 87;
  console.log(mark); // 87
}

../js/lesson.js — Topic 5

6 Function declaration vs expression

Declaration: hoisted as callable before its line. var foo = function () {}: foo is undefined until assignment → early call → TypeError. const foo = () => {}: TDZ → early call → ReferenceError.

sayHi();
function sayHi() { console.log("Hi"); }

greet();
var greet = function () { console.log("Hello"); }; // TypeError

welcome();
const welcome = () => console.log("Welcome"); // ReferenceError (TDZ)

../js/lesson.js demonstrates each inside try/catch where needed.

7 Why this matters in practice
  • Reading legacy var code — hoisting explains “impossible” order.
  • TypeError: … is not a function at the top of a file — often a function expression called before assignment.
  • Stack traces — each frame is an execution context; top = where the error surfaced.
  • Linters (no-var, no-use-before-define) — prevent TDZ / hoisting bugs.

Rule of thumb: read var in old code; write let/const. Don’t rely on hoisting for control flow.
